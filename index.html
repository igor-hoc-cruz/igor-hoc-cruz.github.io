Live Email

Authenticated the sender and cleaned the lists. The domain now holds its warm-up limit of 14,000 sends a day.

  1. The problem

    A lot of email going out, a high bounce rate, and a domain with two DMARC records that cancelled each other out.

  2. What I did

    Backed up the DNS, merged the DMARC records, set up a custom return path and suppressed thousands of invalid addresses and problem domains.

  3. What changed

    The sender passes SPF, DKIM, DMARC and return path checks, and warm-up sits steadily at 14,000 sends a day.

  • GoHighLevel
  • Zoho Marketing Automation
  • Cloudflare DNS
  • SPF, DKIM and DMARC
Live Automation

Half of one campaign’s leads were being dropped without a trace. I found out why and rebuilt the route.

  1. The problem

    The CRM silently rejected anyone whose phone number was already on file, so half the leads from one Meta campaign never became deals.

  2. What I did

    Traced the runs in n8n and rebuilt the route with duplicate handling, re-entry for the new product, alerts, and the company’s official field standard.

  3. What changed

    The lost leads came back as deals, every failure now raises an alert, and all sources send channel, UTMs and ad IDs.

  • n8n
  • Zapier
  • Zoho CRM API
  • Meta Lead Ads
In progress Data

Almost no lead had a recorded source. The cause was an iframe; the fix is a read-only classifier.

  1. The problem

    Leads reached the CRM without a source, so nobody could say what a lead or a customer cost per channel.

  2. What I did

    Found the cause: the quote form runs inside an iframe that never sees the page’s UTMs. Designed a separate, read-only flow that classifies each lead’s channel.

  3. What changed

    Classification logic built and tested, writing to Zoho Analytics, without touching any flow already in production.

  • n8n API
  • JavaScript
  • Zoho Analytics
  • Automated tests

Personal project Personal

Something I build for myself: a character that reacts and speaks, with lip-sync and no cloud services.

  1. The problem

    I wanted to learn real-time 3D and speech end to end, without paid APIs or anything running in the cloud.

  2. What I did

    Built an Electron app that renders a VRM character with three.js, with about 300 scripted actions and 98 motion clips, plus a close-up face view that syncs lips, blinks and gaze to the voice. A Python pipeline drives Blender to render animation sets.

  3. What changed

    Everything runs on a laptop. Speech is generated locally with an open-source text-to-speech model, and the face moves with it in real time.

  • Electron
  • three.js and three-vrm
  • Blender Python API
  • Kokoro TTS
  • Node.js

How I work

  • Understand the need first

    I start from what people need and which data is missing. The tool comes after.

  • Don’t break what works

    Big changes go in next to production, with a backup and a way back.

  • Done means checked

    Every delivery has concrete completion checks and only counts once it is tested.

  • Client data stays protected

    No personal data in code or reports, the least access an integration needs, and approval before acting.
